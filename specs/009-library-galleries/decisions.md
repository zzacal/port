# Decisions: 009 Library and Gallery Management

Source: DEFAULT means the recommended option was taken because the owner was away; OWNER means the
owner chose it. Pivot cost is the cost to reverse after implementation.

| # | Decision | Rationale | Pivot cost | Source |
|---|---|---|---|---|
| 1 | Seeded content removal: retire the seed command, manifest and seed-only code; add a one-time removal command, guarded to development targets, that deletes seeded images (as image deletes) and seeded galleries (as gallery deletes) and reports counts. Upload's validation and camera readers stay. Owner content is never touched. (Clarify Q1) | The roadmap says the seeded content "is removed"; leaving the seed runnable would let it come back. A command, not an automatic startup step, keeps the destructive action explicit and reuses the III.10 target guard. Alternatives: keep the seed restricted to tests (keeps dead production code), or delete by hand in Mongo (no guard, no record). | Low: the seeder is in git history; restoring it is a revert plus re-preparing photos. | DEFAULT |
| 2 | Library paging: newest first, 100 per page, Previous and Next; selection and bulk actions are limited to the page shown, so a bulk action covers at most 100 photos. (Clarify Q2) | Keeps the library page inside its 500 ms bound (SC-002) at the design's 5,000-image scale and gives bulk actions a visible limit before pressing anything (selection-time limit rule). Alternatives: one long page (slow at scale), infinite scroll (needs scripts, unbounded selections). | Low: page size is a setting; cross-page selection could be added later. | DEFAULT |
| 3 | Delete with shared public files: a public file is deleted only when no remaining image references it; the master is always deleted; purge covers only the files actually deleted. (Clarify Q3) | Public files are content-named, so the same photo uploaded twice shares them (008 decisions row 15). Deleting one image must not break the other's pages. Alternative: always delete (breaks the twin), or never delete public files (violates L-09 hard delete). | Low: one reference check in the delete path. | DEFAULT |
| 4 | Publishing asks once, naming the gallery and photo count (005 VisibilityToggle Warning state); unpublishing is immediate; an empty gallery's switch is disabled with the reason and the server refuses too (II.6). (Clarify Q4) | Publishing is the one action that exposes photos (II.5), so it gets one confirmation; hiding is safe and reversible. The 005 contract already designed the warning. Alternative: no confirmation (one misclick publishes), or confirm both (friction on the safe direction). | Low: drop or add a confirmation step. | DEFAULT |
| 5 | Concurrent edits: reorders are refused when the set of photos or galleries changed since the page loaded ("changed in another tab, reload"); text saves are last write wins. (Clarify Q5) | A reorder sent from a stale page could silently drop or re-add members and break FR-036's membership invariant; text saves cannot. Single owner, so full optimistic locking is not worth it. Alternative: last write wins everywhere (membership corruption), or version every document (more code for one user). | Low: a set comparison in the reorder handler. | DEFAULT |
| 6 | Purge credentials are absent: purge and warm sit behind a replaceable interface with a log-only implementation when unconfigured, a development-zone implementation (image file URLs only until hosting), and a recorder for tests. Real credentials are a post-build owner prerequisite, not a blocker. | Owner instruction for this run: nothing may wait on the purge credentials. The recorder makes FR-038's address sets testable without a zone. | Low: wiring the real implementation is configuration. | OWNER |
| 7 | Pages of private galleries that hold photos are purged and warmed too, not only public ones (FR-038). | They are reachable by link and edge-cacheable, so a stale private page would show removed or renamed photos. Widens the design's "if the gallery is public" lifecycle text; the plan records it in the design record (VII.2). | Low: narrows back to public-only by one condition. | DEFAULT |
| 8 | Per-item builder controls (drag handle, cover control, Remove) sit in a row under the tile title, not as corner overlays on the cell as the 005 contract drew them (FR-004). | Owner's standing rule for letterboxed grids: corner overlays float off small portraits or cover photos. Only the library selection mark stays over the photo. Changes the 005 GalleryBuilder and admin ContactSheet /ui/ specimens. | Low: markup and CSS in two organisms. | DEFAULT |
| 9 | Library View link opens the image's photo page in the first gallery (home order) that has a page; no View link when none exists (FR-005). | Every studio row links to its visitor view; an image has no page of its own outside a gallery. | Low. | DEFAULT |
| 10 | Purge and warm run after the save, never inside the owner's request; failures are logged only, no owner alert (FR-040). | IV.18 bounded lifetimes self-heal; delaying or failing the owner's save on a cache provider would be worse. | Low: an alert line could be added to the page. | DEFAULT |
| 11 | Bulk add and bulk delete call the same single-item paths and rules, skipping or reporting per item (FR-012, FR-013). | A bulk transition must reuse the single-item gate, never a laxer one. | Low. | DEFAULT |
| 12 | The library and builder carry no validation nags: no required-field warnings, no missing-caption prompts; limits are enforced at typing time from server settings and refused by the server (FR-007, FR-010). | A bulk working surface is not a validation screen; limits are enforced at selection time and sourced from server config. | Low. | DEFAULT |
| 13 | `GalleryDoc.SeedKey` becomes optional and omitted for owner galleries (FR-048), following 008 decisions row 43. The partial unique index from 008 row 60 already covers it. | Owner galleries must not look seeded, and a second gallery without a seed key must not hit DuplicateKey. | Low. | DEFAULT |
| 14 | The local output cache evicts each affected page on change (FR-044), replacing the seed's "restart the app" instruction. | The owner works on localhost without an edge, so the 60 s origin cache is the only stale layer they see. | Low. | DEFAULT |
