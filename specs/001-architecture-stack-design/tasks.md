# Tasks: End-to-End Architecture and Stack Design

**Input**: Design documents from `/specs/001-architecture-stack-design/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/design-doc-contract.md,
decisions.md, and research-notes/ (all present).

**Tests**: This is a documents-only feature. The "tests" are the contract validation scripts in
`evidence/`. They are written FIRST (Phase 2) and must FAIL against the empty skeleton before any
content is written. A script that passes on an empty document is measuring nothing.

**Organization**: Tasks are grouped by user story. Each story owns separate fragment files, so
stories can be written in parallel without editing the same file.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on incomplete tasks)
- **[Story]**: The user story the task belongs to (US1–US5 from spec.md)

## Path conventions

- FD = `specs/001-architecture-stack-design` (the feature directory)
- Fragments: `FD/draft/NN-<name>.md`. Each holds one top-level section of the design document
  (or one slice of section 2) and starts with that section's exact `##` heading from contract C1.
- The deliverable is `docs/design.md`. It is GENERATED by `FD/evidence/assemble.sh`, which
  concatenates the fragments in filename order. Never edit `docs/design.md` by hand.

## Rules for every executor (read before any task)

1. **No new decisions.** Every Choice, Alternative, number, and price MUST come from
   `FD/research.md`, `FD/decisions.md`, `FD/data-model.md`, `FD/spec.md`, or
   `.specify/memory/constitution.md` (v3.0.0). If a fact you need is not in those files, STOP and
   report it as a blocker. Do not research it and do not guess. Design decisions escalate (Workflow
   rule in the constitution).
2. **Follow the contract literally.** Use the headings, labels, ordering, and allowed values in
   `FD/contracts/design-doc-contract.md`. Write labels exactly, for example `**Pivot cost**:`,
   never "Pivot Cost:".
3. **Cite as you write.** Every decision Rationale cites its source in parentheses, for example
   `(research R-04; decisions #5; Constitution VIII.1)`. Every external fact keeps its research-note
   tag, for example `[asl Q4]`.
4. **Banned strings**: `TBD`, `TODO`, `NEEDS CLARIFICATION`, and `??`. Validation fails on them.
5. **Out of scope** (FR-022): deployment steps, provisioning commands, CI/CD, and
   infrastructure-as-code. These are mentioned only as deferred items in section 10.
6. **Validation scripts are not yours to edit.** If `validate.sh` fails on your fragment, fix the
   fragment. A failing check means the content is wrong, not the script. Only T003 and T004 may
   change the scripts.
7. Plain markdown. Mermaid is used only for the four diagrams. Wrap lines at about 100 characters.
